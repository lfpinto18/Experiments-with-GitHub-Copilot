Introdução

Bem-vindo à documentação do Cream Design System. Este sistema fornece os blocos de construção fundamentais, diretrizes de estilo e padrões de componentes para o desenvolvimento de nossos produtos digitais.

O objetivo é garantir consistência visual, usabilidade e acessibilidade em todas as nossas interfaces.

Princípios

  • Acessibilidade Primeiro: Projetamos e construímos para todos, garantindo conformidade com as diretrizes WCAG.
  • Consistência: Componentes e estilos reutilizáveis garantem uma experiência de usuário unificada.
  • Eficiência: Acelera o processo de design e desenvolvimento.
  • Flexibilidade: Adaptável a diferentes contextos e necessidades de produto.

Componentes

Esta seção documentará os componentes reutilizáveis da interface do usuário (ex: Botões, Inputs, Cards, Modais).

Botão

O componente de botão padrão. Use a classe .btn para estilos básicos e .btn-primary para a variação primária.

Exemplo:

Código:

<button class="btn btn-primary">Botão Primário</button>
<button class="btn btn-primary" disabled>Botão Desabilitado</button>

Diretrizes de Acessibilidade:

  • Deve ter texto descritivo claro que indique a ação.
  • Deve ser focável e operável pelo teclado (use a tecla Tab para navegar e Enter/Espaço para ativar).
  • Estados de foco, hover e ativo devem ser visualmente distintos (fornecidos por button.css).
  • Garantir contraste suficiente entre o texto do botão e seu fundo (Verifique a variável --text-color-primary vs --background-color-primary-button em colors.css. Pode ser necessário usar --text-color-on-dark se o contraste for baixo).
  • Use o atributo disabled para desabilitar botões programaticamente.
  • Para botões que usam apenas ícones, forneça um texto alternativo acessível (ex: usando aria-label ou texto visualmente oculto).

Alerta

Componente para exibir mensagens importantes ou feedback para o usuário. Use as classes .alert e modifique com .alert-info, .alert-success, .alert-warning, ou .alert-error.

Adicione role="alert" para mensagens críticas (ex: erros) ou role="status" para mensagens informativas (ex: sucesso) para acessibilidade.

Para tornar um alerta dispensável, adicione um botão com a classe .alert-close e o atributo aria-label="Fechar alerta".

Exemplos:

Esta é uma mensagem informativa.
Operação realizada com sucesso!
Atenção: Verifique os dados inseridos.
Ocorreu um erro ao processar a solicitação.

Código:

<!-- Alerta Informativo (dispensável) -->
<div class="alert alert-info" role="status">
  Esta é uma mensagem informativa.
  <button class="alert-close" aria-label="Fechar alerta">×</button>
</div>

<!-- Alerta de Erro (dispensável) -->
<div class="alert alert-error" role="alert">
  Ocorreu um erro.
  <button class="alert-close" aria-label="Fechar alerta">×</button>
</div>

Diretrizes de Acessibilidade:

  • Use role="alert" para mensagens críticas que precisam ser anunciadas imediatamente por leitores de tela.
  • Use role="status" para mensagens informativas que podem ser anunciadas quando o leitor de tela estiver ocioso.
  • Garanta contraste suficiente entre o texto e o fundo de cada variante do alerta.
  • O botão de fechar (.alert-close) deve:
    • Ter um rótulo acessível claro (ex: aria-label="Fechar alerta").
    • Ter uma área de toque adequada (mínimo 44x44px seguindo WCAG 2.5.5 nível AAA).
    • Ter estados de foco visíveis e distintos para usuários de teclado.
    • Ser operável pelo teclado (navegável com Tab e ativável com Enter/Espaço).
    • Ter suporte para modo de alto contraste.
  • Se usar ícones SVG, adicione aria-hidden="true" para evitar anúncios duplicados pelos leitores de tela.
  • Para alertas com conteúdo mais complexo, use .alert-content para estruturar o conteúdo e .alert-heading para títulos.
  • Respeite a preferência prefers-reduced-motion para animações.

Card

Cards são contêineres flexíveis para agrupar conteúdo relacionado, como imagens, texto e ações.

Use a classe base .card. Você pode adicionar seções como .card-header, .card-body, .card-footer, e .card-image.

Exemplo:

[Imagem Placeholder]

Título do Card

Este é um texto de exemplo dentro do corpo do card. Ele descreve o conteúdo apresentado.

Código:

<div class="card">
  <div class="card-image">
    <!-- Seu elemento de imagem aqui -->
    <img src="..." alt="Descrição concisa da imagem"> 
  </div>
  <div class="card-body">
    <h4 class="card-title">Título do Card</h4>
    <p>Descrição ou conteúdo do card.</p>
  </div>
  <div class="card-footer">
    <!-- Ações ou informações adicionais -->
    <button class="btn btn-primary btn-sm">Ação</button>
  </div>
</div>

Diretrizes de Acessibilidade:

  • Garanta que a estrutura do cabeçalho (ex: .card-title usando h4 ou similar) seja apropriada para a hierarquia da página.
  • Se o card inteiro for um link clicável, certifique-se de que ele tenha um estado de foco claro e que o propósito do link seja óbvio.
  • Imagens dentro do card (.card-image) devem ter texto alternativo (alt) descritivo, a menos que sejam puramente decorativas.
  • Ações (botões, links) dentro do card devem seguir as diretrizes de acessibilidade para esses elementos (texto claro, foco, operabilidade por teclado).

Modal

Modais são janelas de diálogo que aparecem sobre o conteúdo principal para exibir informações importantes ou solicitar entrada do usuário.

A estrutura básica envolve um contêiner .modal (inicialmente oculto) e o conteúdo .modal-content com .modal-header, .modal-body, e .modal-footer.

A exibição/ocultação geralmente requer JavaScript para adicionar/remover uma classe (ex: .modal-open) no <body> ou no próprio modal.

Exemplo (Estrutura HTML):

Título do Modal

Este é o conteúdo principal do modal. Pode conter formulários, texto, imagens, etc.

Código (Estrutura HTML):

<!-- Botão para abrir o modal -->
<button class="btn btn-primary" data-modal-target="#meuModal">Abrir Modal</button>

<!-- Estrutura do Modal -->
<div class="modal" id="meuModal" aria-labelledby="modalLabel" aria-hidden="true" role="dialog">
  <div class="modal-content" role="document">
    <div class="modal-header">
      <h4 class="modal-title" id="modalLabel">Título do Modal</h4>
      <button class="modal-close" aria-label="Fechar modal" data-modal-close>×</button>
    </div>
    

      
Conteúdo do modal...

    

    

      
      
    

  </div>
</div>

Melhores Práticas:

  • Não use modais como páginas inteiras: Modais devem ser usados para interações breves e focadas, não como substitutos para páginas completas.
  • Casos de uso apropriados:
    • Confirmações (ex: "Tem certeza que deseja excluir?").
    • Formulários curtos (login, inscrição em newsletter).
    • Exibição de informações complementares que não justificam uma navegação de página completa.
    • Ampliação de imagens ou visualização detalhada de elementos.
  • Evite:
    • Formulários extensos ou complexos.
    • Conteúdo que é essencial para a navegação principal.
    • Informações críticas que todos os usuários precisam ver.
    • Empilhar modais (modal dentro de modal).
    • Modais que ocupam toda a tela - neste caso, use uma página separada.
  • Tamanho adequado: O conteúdo deve caber confortavelmente na janela sem exigir rolagem excessiva. Se precisar de muito espaço vertical, considere uma página dedicada.
  • Sempre forneça uma saída clara: Botões de fechar visíveis, possibilidade de fechar com tecla ESC e clicando fora do modal.

Diretrizes de Acessibilidade:

  • Use role="dialog" ou role="alertdialog" no contêiner principal do modal (.modal).
  • Use aria-labelledby para associar o título visível (.modal-title) ao modal. O ID referenciado deve estar no elemento do título.
  • Use aria-describedby (opcional) se houver um texto descritivo principal no modal que deva ser anunciado.
  • Gerencie o atributo aria-hidden: deve ser "true" quando o modal está fechado e "false" (ou removido) quando aberto.
  • Gerenciamento de Foco:
    • Quando o modal abre, o foco deve ser movido para dentro dele (geralmente para o primeiro elemento focável, como o botão de fechar ou um input).
    • O foco deve ser "preso" (trap) dentro do modal enquanto ele estiver aberto (Tab e Shift+Tab não devem sair do modal).
    • Quando o modal fecha, o foco deve retornar ao elemento que o abriu originalmente (ex: o botão "Abrir Modal").
  • O botão de fechar (.modal-close) deve ser operável pelo teclado e ter um aria-label claro.
  • Permitir fechar o modal com a tecla Escape.
  • O conteúdo fora do modal deve ser inerte (não interagível) quando o modal está aberto (pode ser feito com aria-hidden="true" nos elementos principais da página ou usando o atributo inert).

Nota: A implementação completa da acessibilidade do modal (gerenciamento de foco, trap de foco, tecla Esc, aria-hidden) requer JavaScript.

Dropdown

Dropdowns permitem que os usuários selecionem um valor de uma lista. Este exemplo usa um botão para acionar um menu suspenso.

A estrutura envolve um contêiner .dropdown, um botão de acionamento (.dropdown-toggle) e o menu (.dropdown-menu) com itens (.dropdown-item).

JavaScript é necessário para alternar a visibilidade do menu, gerenciar o estado (aberto/fechado), lidar com a seleção e implementar a acessibilidade (ARIA, navegação por teclado).

Exemplo:

Código (Estrutura HTML):

<div class="dropdown" data-component="dropdown">
  <!-- Botão que abre o dropdown -->
  <button class="btn dropdown-toggle" type="button" id="dropdownMenuButton" 
          aria-haspopup="listbox" aria-expanded="false">
    Selecione...
  </button>
  
  <!-- O menu dropdown -->
  <ul class="dropdown-menu" aria-labelledby="dropdownMenuButton" role="listbox">
    <li>
      <button class="dropdown-item" type="button" role="option" data-value="valor1">
        Item 1
      </button>
    </li>
    <li>
      <button class="dropdown-item" type="button" role="option" data-value="valor2">
        Item 2
      </button>
    </li>
    <li><hr class="dropdown-divider"></li> <!-- Separador opcional -->
    <li>
      <button class="dropdown-item" type="button" role="option" data-value="valor3">
        Outro Item
      </button>
    </li>
  </ul>
</div>

Diretrizes de Acessibilidade:

  • O botão de acionamento (.dropdown-toggle) deve ter:
    • aria-haspopup="listbox" para indicar que controla um menu de opções.
    • aria-expanded="true/false" para indicar o estado do menu (gerenciado por JS).
    • Um ID único para ser referenciado por aria-labelledby no menu.
  • O contêiner do menu (.dropdown-menu) deve ter:
    • role="listbox" para definir sua função.
    • aria-labelledby referenciando o ID do botão de acionamento.
  • Cada item clicável dentro do menu (.dropdown-item) deve ter:
    • role="option".
    • aria-selected="true/false" (opcional, se precisar indicar a seleção atual visualmente e para leitores de tela).
    • Ser um <button> ou <a> para ser focável e operável por teclado.
  • Gerenciamento de Foco e Teclado (Requer JS):
    • Quando o menu abre, o foco deve ir para o primeiro item (ou o item selecionado).
    • Setas Cima/Baixo devem navegar entre os itens.
    • Enter ou Espaço devem selecionar o item focado e fechar o menu.
    • Escape deve fechar o menu sem selecionar.
    • Tab deve fechar o menu e mover o foco para o próximo elemento focável fora do dropdown.
    • Clicar fora do menu deve fechá-lo.

Nota: A implementação completa da acessibilidade e funcionalidade do dropdown requer JavaScript robusto.

Opções de Alinhamento de Texto:

O dropdown permite diferentes opções de alinhamento de texto para adaptar-se a diversos layouts:

  • Item Alinhado à Esquerda
  • Outro Item
  • Item Centralizado
  • Outro Item
  • Item Alinhado à Direita
  • Outro Item

Código para Alinhamentos:

<!-- Dropdown com alinhamento padrão (esquerda) -->
<div class="dropdown" data-component="dropdown">
  <button class="btn dropdown-toggle" type="button" id="dropdownDefault" 
          aria-haspopup="menu" aria-expanded="false">
    Alinhamento Esquerda
  </button>
  <ul class="dropdown-menu" aria-labelledby="dropdownDefault" role="menu">
    <li><a href="#" class="dropdown-item" role="menuitem">Item Alinhado à Esquerda</a></li>
    <li><a href="#" class="dropdown-item" role="menuitem">Outro Item</a></li>
  </ul>
</div>

<!-- Dropdown com alinhamento central -->
<div class="dropdown" data-component="dropdown">
  <button class="btn dropdown-toggle text-center" type="button" id="dropdownCentered" 
          aria-haspopup="menu" aria-expanded="false">
    Alinhamento Centro
  </button>
  <ul class="dropdown-menu dropdown-menu-centered" aria-labelledby="dropdownCentered" role="menu">
    <li><a href="#" class="dropdown-item" role="menuitem">Item Centralizado</a></li>
    <li><a href="#" class="dropdown-item" role="menuitem">Outro Item</a></li>
  </ul>
</div>

<!-- Dropdown com alinhamento direita -->
<div class="dropdown" data-component="dropdown">
  <button class="btn dropdown-toggle text-right" type="button" id="dropdownRight" 
          aria-haspopup="menu" aria-expanded="false">
    Alinhamento Direita
  </button>
  <ul class="dropdown-menu dropdown-menu-right-aligned" aria-labelledby="dropdownRight" role="menu">
    <li><a href="#" class="dropdown-item" role="menuitem">Item Alinhado à Direita</a></li>
    <li><a href="#" class="dropdown-item" role="menuitem">Outro Item</a></li>
  </ul>
</div>

Tabs

Tabs permitem organizar conteúdo em seções separadas que podem ser exibidas uma de cada vez.

A estrutura envolve uma lista de controles de tab (.tab-list com role="tablist"), cada um sendo um botão (.tab-item com role="tab"), e os painéis de conteúdo correspondentes (.tab-panel com role="tabpanel").

JavaScript é essencial para alternar a visibilidade dos painéis, gerenciar os atributos ARIA de estado (aria-selected, aria-controls) e implementar a navegação por teclado.

Exemplo:

Conteúdo do Painel 1. Este é o conteúdo inicial visível.

Conteúdo do Painel 2.

Conteúdo do Painel 3. Mais informações aqui.

Código (Estrutura HTML):

<div class="tabs" data-component="tabs">
  <!-- Lista de controles das abas -->
  <div class="tab-list" role="tablist" aria-label="Nome descritivo do conjunto de abas">
    <button class="tab-item" role="tab" id="tab-ex1" 
            aria-controls="panel-ex1" aria-selected="true">
      Título Aba 1
    </button>
    <button class="tab-item" role="tab" id="tab-ex2" 
            aria-controls="panel-ex2" aria-selected="false" tabindex="-1">
      Título Aba 2
    </button>
    <button class="tab-item" role="tab" id="tab-ex3" 
            aria-controls="panel-ex3" aria-selected="false" tabindex="-1">
      Título Aba 3
    </button>
  </div>

  <!-- Painéis de conteúdo -->
  <div class="tab-panel" role="tabpanel" id="panel-ex1" aria-labelledby="tab-ex1">
    <p>Conteúdo da Aba 1...</p>
  </div>
  <div class="tab-panel" role="tabpanel" id="panel-ex2" aria-labelledby="tab-ex2" hidden>
    <p>Conteúdo da Aba 2...</p>
  </div>
  <div class="tab-panel" role="tabpanel" id="panel-ex3" aria-labelledby="tab-ex3" hidden>
    <p>Conteúdo da Aba 3...</p>
  </div>
</div>

Diretrizes de Acessibilidade:

  • O contêiner da lista de abas (.tab-list) deve ter role="tablist" e um aria-label descritivo.
  • Cada botão de aba (.tab-item) deve ter:
    • role="tab".
    • aria-selected="true/false" indicando se é a aba ativa (gerenciado por JS). Apenas uma aba deve ter true.
    • aria-controls referenciando o ID do painel de conteúdo correspondente.
    • Um ID único para ser referenciado por aria-labelledby no painel.
    • tabindex="0" para a aba ativa e tabindex="-1" para as inativas (gerenciado por JS) para navegação por teclado.
  • Cada painel de conteúdo (.tab-panel) deve ter:
    • role="tabpanel".
    • aria-labelledby referenciando o ID do botão de aba correspondente.
    • O atributo hidden para painéis inativos (gerenciado por JS).
  • Gerenciamento de Foco e Teclado (Requer JS):
    • Setas Esquerda/Direita (ou Cima/Baixo se aria-orientation="vertical") devem mover o foco entre os botões de aba (.tab-item). A ativação da aba (mostrar painel) pode ocorrer ao mover o foco ou ao pressionar Enter/Espaço.
    • Home deve mover o foco para a primeira aba.
    • End deve mover o foco para a última aba.
    • Tab deve mover o foco para fora do componente de abas (para o painel ativo ou para o próximo elemento focável após a lista de abas).

Diretrizes de Acessibilidade

A acessibilidade é um pilar fundamental deste design system. Todos os componentes e padrões devem seguir as WCAG (Web Content Accessibility Guidelines) 2.1 nível AA como mínimo.

  • Contraste de Cores: Mantenha relações de contraste adequadas.
  • Navegação por Teclado: Todos os elementos interativos devem ser acessíveis e operáveis via teclado.
  • Foco Visível: Indicadores de foco claros são essenciais.
  • Semântica HTML: Use elementos HTML semanticamente corretos (<nav>, <button>, <main>, etc.).
  • ARIA: Use atributos ARIA (Accessible Rich Internet Applications) quando necessário para melhorar a semântica de componentes complexos.
  • Texto Alternativo: Forneça texto alternativo descritivo para imagens.
  • Formulários Acessíveis: Use labels associadas corretamente aos inputs.
  • Responsivo e Zoom: O conteúdo deve ser acessível em ampliações de até 200% e em diferentes tamanhos de tela.
  • Testes com Leitores de Tela: Valide todos os componentes com softwares leitores de tela como NVDA, JAWS e VoiceOver.
  • Compatibilidade com Alto Contraste: Verifique se os componentes são utilizáveis em modo de alto contraste.
